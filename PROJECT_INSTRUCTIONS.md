## КРИТИЧНЫЕ ПРАВИЛА

### 1. Одна задача за раз
- Выполняется ОДНА задача
- После выполнения - СТОП и ждать подтверждения от пользователя
- Только после подтверждения - следующая задача

### 2. Декомпозиция задач
- Каждая задача разбивается на мелкие атомарные шаги
- Один шаг = одно изменение или одна проверка

### 3. ДВОЙНОЕ ПОДТВЕРЖДЕНИЕ ДЕЙСТВИЙ (ОБЯЗАТЕЛЬНО)

Каждое действие требует ДВА подтверждения:

| Действие | 1. Пакет от сервера | 2. Бот знает и логирует |
|----------|---------------------|-------------------------|
| Lock target | Сервер прислал подтверждение лока | Бот: "Target locked: [name]" |
| Attack | Сервер прислал подтверждение атаки | Бот: "Attacking: [name]" |
| Collect box | Сервер прислал подтверждение сбора | Бот: "Collected: [item]" |
| Move | Сервер прислал подтверждение движения | Бот: "Moving to: [x,y]" |
| Use item | Сервер прислал подтверждение | Бот: "Used: [item]" |

**ЛОГИКА:**
```
Бот отправил команду → Сервер ответил пакетом → Бот ОБРАБОТАЛ ответ → Бот ЗНАЕТ свой статус
```

**БЕЗ ОБОИХ ПОДТВЕРЖДЕНИЙ - ДЕЙСТВИЕ НЕ СЧИТАЕТСЯ РАБОТАЮЩИМ!**

Бот НЕ должен:
- ❌ "Думать" что атакует, не получив подтверждение
- ❌ "Думать" что взял в лок, не получив подтверждение
- ❌ Продолжать действие вслепую без ответа сервера

Бот ДОЛЖЕН:
- ✅ Отправить команду
- ✅ Дождаться ответа сервера
- ✅ Обработать ответ и обновить своё состояние
- ✅ Залогировать что действие ПОДТВЕРЖДЕНО

### 4. Критерий выполнения задачи
- ✅ Билд успешен
- ✅ Бот запускается
- ✅ В логах есть ПАКЕТ от сервера (подтверждение)
- ✅ В логах есть ОБРАБОТКА ботом (бот знает статус)
- ✅ Коммит сделан
- ✅ Документация обновлена

## Пример полного цикла задания

1. **Чат решает ОДНУ ПРОБЛЕМУ**, разбивая её на мелкие шаги
   - Каждый шаг = отдельный вызов `claude-code-mcp:claude_code`
   - После каждого шага - проверка результата
   - Следующий шаг только после успеха предыдущего

2. **CLI выполняет ОДИН ШАГ**:
   - Вносит изменения в код
   - Запускает `.\gradlew build`
   - Запускает `timeout 20 .\gradlew run`
   - Анализирует логи

3. **CLI проверяет ДВОЙНОЕ подтверждение**:
   - Пакет от сервера есть? ✅/❌
   - Бот обработал и знает статус? ✅/❌

4. **CLI возвращает отчёт** с ОБОИМИ доказательствами

5. **Чат проверяет результат шага**:
   - Успех → следующий шаг той же проблемы
   - Неудача → исправление

6. **После решения ВСЕЙ проблемы**:
   - CLI документирует (CHANGELOG, IMPLEMENTATION_PLAN)
   - Коммит
   - СТОП - ждёт подтверждения пользователя

7. **Пользователь подтверждает** - только тогда следующая ПРОБЛЕМА
